# fork 自定义检查

这里的每个 `.sh` 都会被 `scripts/ci.sh verify` 自动执行，**不用改 ci.sh，也不用改
`.github/workflows/`**。

这是给 fork 的标准落点：

| 你想加什么 | 怎么做 |
|---|---|
| 一道自己的门禁 | 往这个目录放一个 `.sh`，退出码非 0 = 失败 |
| 项目级的约定（比如「不许直接调 Retrofit」） | 同上，放个脚本进去 |
| 已有门禁的例外 | 在脚本里自己判（脚本自己知道哪些是例外） |

约定：

- 脚本自己 `cd` 到仓库根（`ci.sh` 已经 cd 过了，但脚本也可能被单独跑，所以自己兜一层）
- 退出码 0 = 通过，非 0 = 失败
- 输出尽量说清「哪里错了」，CI 日志里直接能看懂
- 跑得快 —— 这道门禁在每个 PR 上都跑

上游只往这里加**它自己命名的文件**（比如 `no-hardcoded-secrets.sh`）。你放的文件名跟它们不重名，
`git pull upstream` 就不会冲掉你那份。真怕撞名，给自己的文件加项目名前缀：`myapp-no-todo-in-compose.sh`。

> 同名才冲突 —— 但真撞上了 git 会告诉你，merge 一下就行，不会丢东西。
